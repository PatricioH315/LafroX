# LafroX — Guía de lectura de la propuesta

Esta carpeta permite entender qué aporta cada documento y elegir dónde profundizar. Contiene **26 resúmenes independientes** de los capítulos **1–8 y 13**: nueve subdocumentos, siete archivos de anexos y diez formularios. Los siete resúmenes de anexos explican **66 anexos individuales**, cada uno con su identificador y enlace al original.

## Por dónde empezar

Para entender la propuesta, sigue problema **2 → alcance 3 → arquitectura 4 → datos 5**. Después revisa empresa **1 → metodología 6 → plan 7 → riesgos 8 → innovaciones 13**. Cada guía explica propósito, ideas principales, datos clave y relaciones.

Usa los resúmenes de anexos cuando necesites una regla, un catálogo, una prueba o un cálculo concreto. Usa los formularios para encontrar la experiencia, especificación, compromiso, paquete o ficha formal. El enlace **original** de la tabla abre la fuente completa.

## Claves para la lectura

| Término | Significado en estas guías |
| --- | --- |
| E1 / E2 | Etapas 1 y 2 de implementación |
| RF / RNF / RT | Requerimiento funcional, no funcional y requisito transversal |
| EDT / HH | Estructura de descomposición del trabajo y horas hombre |
| OTIF | Entrega completa dentro de la fecha y ventana comprometidas |
| WMS / ERP | Gestión de bodega / sistema empresarial que conserva la emisión tributaria |
| POD / DTE | Prueba de entrega / documento tributario electrónico |
| RTO / RPO | Tiempo objetivo de recuperación / antigüedad máxima de los datos recuperables |
| TRL | Nivel de madurez declarado de una tecnología o propuesta |

## Alcance y actualización

**Fuentes:** archivos locales vigentes al **8 de octubre de 2026**, incluidos cambios sin registrar disponibles al preparar las guías. Se excluyen Bases, material del curso, revisiones, catálogos auxiliares y el borrador de innovaciones. Los nombres conservan el original y agregan `-Resumen.md`.

Los resúmenes son ayudas de lectura; los detalles y compromisos se consultan en la fuente. Distinguen requisitos, propuestas, cálculos, supuestos y verificaciones pendientes. Un «Sí» en T-12 es un compromiso y un protocolo no es una prueba ejecutada. Las diferencias se señalan sin corregir la oferta, como el número de resultados E1 descrito en SD7 o las responsabilidades/calendario de sala técnica.

Al cambiar un original, actualizar su resumen y los relacionados que usen la misma cifra o decisión. Si se incorpora otro entregable, añadir su resumen y entrada en esta tabla. Mantener identificadores y enlaces por sección; no completar vacíos con suposiciones. La carpeta no se actualiza automáticamente.

**Uso de IA:** guías elaboradas con asistencia de Codex para síntesis, organización y comprobación de referencias locales. No acreditan revisión humana adicional, certificaciones externas, aprobación del CLIENTE ni ejecución de los ensayos.
